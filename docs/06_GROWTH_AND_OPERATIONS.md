# KidGem growth and operations

## Positioning
KidGem helps children build math, reasoning, coding and language skills through clear, short learning adventures. English, French and Bengali are a distinctive editorial direction. Do not market all-grade completeness, adaptive AI, certified alignment or improved intelligence before those claims have evidence.

## Design for discovery
Publish useful subject and skill pages that parents and teachers can understand without signing in. Each published skill page includes objective, age/level guidance, a worked example, a playable sample and an offline extension. Give every page descriptive titles, headings, metadata, a canonical URL and truthful structured data when applicable. Do not create hundreds of empty grade/locale pages. Keep private profiles and parent routes out of search indexing; robots directives are not access control.

The hash-routed demo prioritizes easy hosting and learning-flow validation. For the public production content site, choose crawlable HTML routes using prerendering or server/static rendering, with real locale URLs and reviewed translations. Do not claim hash routes provide equivalent discoverability. Keep the learning app and content catalogue linked consistently during this transition.

## First pilot
Recruit 10–15 families through founder-approved invitations, covering younger learners, older learners and the intended languages. Observe with guardian involvement and permission. Test starting a lesson, understanding instructions, recovering from an error, finding the next step and returning later. Collect adult feedback; do not publish child identities, pictures or quotes without a separate permission process. Fix repeated confusion before adding more games.

## Proposed launch sequence
Stage 1: validate the full learning loop with the 12-lesson demo. Stage 2: family beta with a real backend and reviewed first paths. Stage 3: publish useful resource pages, teacher demonstration material and short gameplay previews. Stage 4: expand content according to observed demand and learning gaps. Stage 5: evaluate school features and a sustainable adult-facing paid plan only after core value is proven.

## Measurement definitions
| Metric | Definition | Use |
|---|---|---|
| Activation | Eligible new profiles completing one learning loop within seven days / eligible new profiles | Onboarding usefulness |
| Lesson completion | Started lesson sessions reaching summary / started lesson sessions | Locate friction; account for intentional pauses |
| Independent mastery | Assessed skills meeting the stated unassisted rule / assessed skills with sufficient evidence | Learning progression, not an IQ score |
| Seven-day return | New activated profiles with another session on days 7–13 / activated profiles with the full observation window | Family return behavior |
| Review retention | Due skills passing a later independent review / due skills actually reviewed | Separate retention from initial success |
| Parent usefulness | Positive responses / adult survey responses, with sample size shown | Family value |

Exclude internal/demo test data and show cohort size and missing observation windows. These are proposed definitions, not claims about current performance. A small pilot supports qualitative changes, not broad statistical claims.

## Event design
Use a disabled-by-default analytics adapter in the demo. Candidate events: path_selected, lesson_started, stage_completed, hint_requested, assessment_submitted, lesson_completed and review_completed. When analytics is enabled after the chosen consent/data review, use pseudonymous IDs and collect only needed subject, level, stage and outcome fields. No advertising trackers, public leaderboards, raw free-text answers, voice recordings or hidden session replay. Document event retention and access.

## Experiments
Compare a clear Continue card with a map-first entry using observed task success. Compare two explanation formats using different but equivalent assessment items. Keep essential teaching and accessibility features available to all groups. Use adult opt-in for optional reminders; do not send child-targeted purchase prompts or punish missed visits.

## Editorial operating rhythm
Weekly: review errors, support requests, misleading feedback and language issues. Before publication: educator and language review plus answer validation. Monthly: inspect path coverage, review results, broken links and device performance. Track content work separately from software work; translating labels does not create a translated curriculum.

## Sustainability
Start with a free demo. Evaluate family subscriptions or school licensing later, with clear adult-facing prices and cancellation. Keep purchases outside the child learning flow. No invented business forecasts or assumed free hosting allowances; check provider prices when choosing services. Assign an owner to support, content review, security maintenance and release approval before launch.
